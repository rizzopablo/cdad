+# Spec: Note tags
+
+This spec opens with the functional description derived from a **user journey**.
+
+**User journey**
+
+- **Actor**: the single local user of notes-cli, at the terminal.
+- **Goal**: tag my notes and then list only the notes that carry a given tag, or any of several given tags.
+- **Legitimate starting point**: a notes file with notes added with `add` and listed with `list`, as today. No note has tags.
+- **First useful result**: the user gives a note one or more tags, and `list --tag <name>` shows only the notes that carry at least one of the given names, with their ids.
+
+The user can give a note several tags when adding it, add or remove tags on an existing note by its id, see each note's tags next to its text in the plain list, and filter the list by one or more tags (a note is shown if it carries any of them). Notes without tags keep working as before.
+
+## Acceptance criteria (observable behavior over the journey)
+
+- [ ] From an empty notes file, the user runs `add "buy milk" --tag home --tag errands` and then `list`, and sees `0: buy milk [home, errands]`.
+- [ ] With notes carrying other tags present, `list --tag home --tag errands` shows only the notes that carry `home` or `errands`, each with its id, and a note that carries both appears once.
+- [ ] The user runs `tag` and `untag` on an existing note id and sees the change in `list`.
+- [ ] If a tag name is invalid (empty, containing a space, tab, `,`, `[` or `]`, or beginning with `--`), or a `--tag` has no name, the command fails with a message naming the first invalid argument (or the missing argument), and the notes file is unchanged. The only silent change is case folding: `Home` is stored and matched as `home`.
+- [ ] Notes without tags, and a notes file written before this feature, list exactly as before.
+
+## Contract (promises, postconditions and invariants)
+
+**Promises (observable, one per user-visible guarantee).** Each postcondition below belongs to exactly one promise.
+
+| Promise | What the user can see | Postconditions |
+| --- | --- | --- |
+| A — Tagging a note when it is added | The note I add carries the tags I gave it, and its text is not polluted by the flags | PC-1, PC-2 |
+| B — Changing tags of an existing note | Tags I add or remove on a note, by its id, appear in the list | PC-3, PC-4, PC-5 |
+| C — Filtering by tag | `list --tag` shows only the notes that carry at least one of the given tags | PC-6 |
+| D — Seeing tags | Plain `list` shows each note's tags next to its text, in a fixed order | PC-7 |
+| E — Tag names are checked | A name is stored in one form (lowercase, once per note); invalid input is refused with a message and nothing changes | PC-8, PC-9, PC-10 |
+| F — Existing notes keep working | Notes without tags, older notes files, and the remaining notes after `rm` keep their text and tags | PC-11, PC-12, PC-13 |
+
+**Verification per promise** (all executable: pytest runs `python -m notes.cli` in a subprocess with `NOTES_FILE` set to a temp path per test; no contextual review is needed, since every promise is observable as printed output or file bytes).
+
+| Promise | Property | Method | Acceptance criterion | Expected evidence | Verification limits |
+| --- | --- | --- | --- | --- | --- |
+| A | Tags given at add are stored; flags never enter the text | executable | `add` with tags, then `list --tag <name>`, shows the note with exactly those tags and clean text | pytest output for the tests of PC-1 and PC-2 | does not cover terminal rendering beyond the asserted lines |

+**Postconditions (numbered and verifiable):**
+
+1. **PC-1 (A):** On an empty notes file, `add "buy milk" --tag home --tag errands` exits with status 0 and prints `0`; a following `list --tag home` prints `0: buy milk [home, errands]`.
+2. **PC-2 (A):** Each of the following, run on its own empty notes file, gives the stated result:
+   - `add buy --tag home milk`; then `list --tag home` gives `0: buy milk [home]`. `--tag` takes exactly the next argument as the name, and the remaining arguments form the text.
+   - `add --tag buy milk`; then `list --tag buy` gives `0: milk [buy]`.
+   - `add "a --tag b"`; then `list` gives `0: a --tag b`, with no tags. An argument that merely contains `--tag` is text, not a flag.
+   - `add "buy home" --tag home`; then `list --tag home` gives `0: buy home [home]`. The word `home` in the text and the tag `home` are independent.
+3. **PC-3 (B):** `tag <id> <name> [<name> ...]` adds each given name to the note with that id and keeps its existing tags; the tags of other notes are unchanged. Tags appear in `[<tags>]` in the order in which they were applied to the note:
+   - names given to `add --tag` or to `tag` go after the names already on the note, in the order given;
+   - a name already on the note keeps its position when it is applied again;
+   - a name removed by `untag` and applied again goes to the end (see PC-4).
+
+   Example: note 0 carries `c`; after `tag 0 a b`, `list --tag c` prints `0: … [c, a, b]`. After `untag 0 a` (PC-4), the note carries `[c, b]`; after `tag 0 a`, `list --tag c` prints `0: … [c, b, a]`.
+4. **PC-4 (B):** `untag <id> <name> [<name> ...]` removes each given name from that note and keeps its other tags in their order: after `untag 0 a` on `[c, a, b]`, `list --tag c` prints `0: … [c, b]`. Untagging a name the note does not carry exits with status 0 and changes nothing: the note's tags are the same, as observed through `list --tag` on each of them.
+5. **PC-5 (B):** An id is accepted only in the form `list` prints it: decimal digits, no sign, no leading zero, and a value less than the number of notes. For `tag` or `untag`, any other id (negative, equal to or above the number of notes, not an integer, or written in another form) exits with non-zero status, prints a message on stderr naming the id as given, and leaves the notes file byte-identical. If the notes file does not exist, it still does not exist after the refusal. When more than one argument is invalid, the message names the first invalid argument, scanning left to right; for `tag` and `untag`, that is the id whenever the id is invalid.
+6. **PC-6 (C):** `list --tag <name> [--tag <name> ...]` prints exactly the notes that carry at least one of the given names, in id order. A note that matches more than one of the names is printed once. Each line is `<id>: <text> [<tags>]`, where `[<tags>]` is all the note's tags, not only the matched ones. Example: note 0 `buy milk` carries `[home, errands]`; note 1 `write report` carries `[work]`; note 2 `pay rent` carries `[errands]`. Then `list --tag home --tag errands` prints `0: buy milk [home, errands]` and `2: pay rent [errands]`, and does not print note 1. Notes that carry none of the names are not printed. If no note carries any of the names, it prints nothing and exits with status 0.
+7. **PC-7 (D):** Plain `list` prints each tagged note as `<id>: <text> [<tags>]`, with tags in the order of PC-3. An untagged note prints as `<id>: <text>` (PC-11). Example: after `add buy milk --tag home --tag errands`, `list` prints `0: buy milk [home, errands]`.
+8. **PC-8 (E):** A name the note already carries is kept once, whether it is repeated in `add` (`--tag home --tag home`) or applied again with `tag`; `list --tag home` shows `[home]`, and the name keeps its position (see PC-3).
+9. **PC-9 (E):** Case folding applies to every name argument of `add --tag`, `tag`, `untag` and `list --tag`: each name is stored and matched in lowercase, silently. Examples: `add x --tag Home`, then `list --tag home`, prints `0: x [home]`; `list --tag HOME` shows that note; `untag 0 HOME` on a note with `[home]` removes `home`, and then `list --tag home` prints nothing. With two names: after `add a --tag Home` and `add b --tag Work`, `list --tag HOME --tag WORK` prints `0: a [home]` and `1: b [work]`.
+10. **PC-10 (E):** Invalid input is refused: it exits with non-zero status, prints a message on stderr that names the first invalid argument (scanning left to right) or, when a value is missing, the missing argument (`id` or `name`), and leaves the notes file byte-identical. Invalid input is:
+    - (a) a tag name that is empty, contains an ASCII space, tab, `,`, `[` or `]`, or begins with `--`, given to `add`, `tag`, `untag` or `list --tag`. Example: `tag 0 --tag` exits with non-zero status, names `--tag` on stderr, and leaves the file unchanged;
+    - (b) `--tag` with no name after it (at the end of the arguments), given to `add` or `list`; for example, `list --tag home --tag` is refused. A trailing `--tag` is reported as the missing argument `name`;
+    - (c) `add` with at least one tag and an empty text: the text arguments are absent or are all empty strings (for example `add --tag home`, or `add "" --tag home`); nothing is written, and no note with tags but no text is created;
+    - (d) `tag` or `untag` with no id, or with an id and no name after it. The message names the id given, or, when no id is given, the missing argument `id`; when only the name is missing, it names the missing argument `name`.
+    - (e) reserved: `list` with arguments other than `--tag <name>` pairs. Pending owner decision (A12). It is not verified and commits nothing.
+
+    In `tag` or `untag` with several names, if any one of them is invalid, none of them is applied.
+11. **PC-11 (F):** A note with no tags prints as `<id>: <text>`, exactly as before this feature. This holds for a note added without `--tag`, and for a note whose tags were all removed: `add x --tag a`, then `untag 0 a`, then `list` prints `0: x`.
+12. **PC-12 (F):** A notes file written before this feature (entries holding only `text`) is read without error: `list` prints its notes as in PC-11; `list --tag <name>` does not print them; `tag 0 <name>` succeeds and `list --tag <name>` then shows `0: … [<name>]`; `rm <id>` still deletes the note at that id.
+13. **PC-13 (F):** After `rm <id>`, each remaining note keeps its own text and tags and takes its new id. Example: `add a --tag a`, `add b --tag b`, `rm 0`; then `list --tag b` prints `0: b [b]`, and `list --tag a` prints nothing.

+"""Notes are kept in notes.json as a JSON list; a note's id is its list index."""
+import json, os
+PATH = os.environ.get("NOTES_FILE", "notes.json")
+
+def load():
+    if not os.path.exists(PATH):
+        return []
+    with open(PATH) as f:
+        return json.load(f)
+
+def save(items):
+    with open(PATH, "w") as f:
+        json.dump(items, f)
+
+def add(text):
+    items = load()
+    items.append({"text": text})
+    save(items)
+    return len(items) - 1
+
+def delete(note_id):
+    items = load()
+    del items[note_id]  # later notes shift down by one
+    save(items)
+
+def all_notes():
+    return list(enumerate(load()))
