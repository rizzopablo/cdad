9: # Spec: Note tags
10: 
11: This spec opens with the functional description derived from a **user journey**.
12: 
13: **User journey**
14: 
15: - **Actor**: the single local user of notes-cli, at the terminal.
16: - **Goal**: tag my notes and then list only the notes that carry a given tag, or any of several given tags.
17: - **Legitimate starting point**: a notes file with notes added with `add` and listed with `list`, as today. No note has tags.
18: - **First useful result**: the user gives a note one or more tags, and `list --tag <name>` shows only the notes that carry at least one of the given names, with their ids.
19: 
20: The user can give a note several tags when adding it, add or remove tags on an existing note by its id, see each note's tags next to its text in the plain list, and filter the list by one or more tags (a note is shown if it carries any of them). Notes without tags keep working as before.
21: 
22: ## Acceptance criteria (observable behavior over the journey)
23: 
24: - [ ] From an empty notes file, the user runs `add "buy milk" --tag home --tag errands` and then `list`, and sees `0: buy milk [home, errands]`.
25: - [ ] With notes carrying other tags present, `list --tag home --tag errands` shows only the notes that carry `home` or `errands`, each with its id, and a note that carries both appears once.
26: - [ ] The user runs `tag` and `untag` on an existing note id and sees the change in `list`.
27: - [ ] If a tag name is invalid (empty, containing a space, tab, `,`, `[` or `]`, or beginning with `--`), or a `--tag` has no name, the command fails with a message naming the first invalid argument (or the missing argument), and the notes file is unchanged. The only silent change is case folding: `Home` is stored and matched as `home`.
28: - [ ] Notes without tags, and a notes file written before this feature, list exactly as before.

57: 2. **PC-2 (A):** Each of the following, run on its own empty notes file, gives the stated result:
58:    - `add buy --tag home milk`; then `list --tag home` gives `0: buy milk [home]`. `--tag` takes exactly the next argument as the name, and the remaining arguments form the text.

61:    - `add "buy home" --tag home`; then `list --tag home` gives `0: buy home [home]`. The word `home` in the text and the tag `home` are independent.
62: 3. **PC-3 (B):** `tag <id> <name> [<name> ...]` adds each given name to the note with that id and keeps its existing tags; the tags of other notes are unchanged. Tags appear in `[<tags>]` in the order in which they were applied to the note:
63:    - names given to `add --tag` or to `tag` go after the names already on the note, in the order given;
64:    - a name already on the note keeps its position when it is applied again;
65:    - a name removed by `untag` and applied again goes to the end (see PC-4).
66: 
67:    Example: note 0 carries `c`; after `tag 0 a b`, `list --tag c` prints `0: … [c, a, b]`. After `untag 0 a` (PC-4), the note carries `[c, b]`; after `tag 0 a`, `list --tag c` prints `0: … [c, b, a]`.
68: 4. **PC-4 (B):** `untag <id> <name> [<name> ...]` removes each given name from that note and keeps its other tags in their order: after `untag 0 a` on `[c, a, b]`, `list --tag c` prints `0: … [c, b]`. Untagging a name the note does not carry exits with status 0 and changes nothing: the note's tags are the same, as observed through `list --tag` on each of them.
69: 5. **PC-5 (B):** An id is accepted only in the form `list` prints it: decimal digits, no sign, no leading zero, and a value less than the number of notes. For `tag` or `untag`, any other id (negative, equal to or above the number of notes, not an integer, or written in another form) exits with non-zero status, prints a message on stderr naming the id as given, and leaves the notes file byte-identical. If the notes file does not exist, it still does not exist after the refusal. When more than one argument is invalid, the message names the first invalid argument, scanning left to right; for `tag` and `untag`, that is the id whenever the id is invalid.
70: 6. **PC-6 (C):** `list --tag <name> [--tag <name> ...]` prints exactly the notes that carry at least one of the given names, in id order. A note that matches more than one of the names is printed once. Each line is `<id>: <text> [<tags>]`, where `[<tags>]` is all the note's tags, not only the matched ones. Example: note 0 `buy milk` carries `[home, errands]`; note 1 `write report` carries `[work]`; note 2 `pay rent` carries `[errands]`. Then `list --tag home --tag errands` prints `0: buy milk [home, errands]` and `2: pay rent [errands]`, and does not print note 1. Notes that carry none of the names are not printed. If no note carries any of the names, it prints nothing and exits with status 0.
71: 7. **PC-7 (D):** Plain `list` prints each tagged note as `<id>: <text> [<tags>]`, with tags in the order of PC-3. An untagged note prints as `<id>: <text>` (PC-11). Example: after `add buy milk --tag home --tag errands`, `list` prints `0: buy milk [home, errands]`.
72: 8. **PC-8 (E):** A name the note already carries is kept once, whether it is repeated in `add` (`--tag home --tag home`) or applied again with `tag`; `list --tag home` shows `[home]`, and the name keeps its position (see PC-3).
73: 9. **PC-9 (E):** Case folding applies to every name argument of `add --tag`, `tag`, `untag` and `list --tag`: each name is stored and matched in lowercase, silently. Examples: `add x --tag Home`, then `list --tag home`, prints `0: x [home]`; `list --tag HOME` shows that note; `untag 0 HOME` on a note with `[home]` removes `home`, and then `list --tag home` prints nothing. With two names: after `add a --tag Home` and `add b --tag Work`, `list --tag HOME --tag WORK` prints `0: a [home]` and `1: b [work]`.
