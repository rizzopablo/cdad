TEXT: Neither assumption holds as you stated it. I checked both by running the CLI on a scratch notes file in a temp folder, not on your data.

**1. Note numbers do not stay the same after a delete. They shift down.**

I added `first`, `second` and `third`, then ran `rm 0`. The list afterwards was:

```
0: second
1: third
```

The cause is in `notes/storage.py:23`: `del items[note_id]`. A note's number is its position in the list, so every later note moves down one. Tags travel with their note, but the number you type changes. If you list, delete, and then tag by the old number, you tag a different note. This is an existing behaviour, and the spec already records it as a limit (deferred-hardening, and PC-13 pins the new numbering). It is now a real choice for you, not a footnote: keep the shifting numbers, or make numbers stable (a bigger change to the storage format).

- Reading: I wrote a file with two old-style notes (`{"text": ...}`) and ran `list`. It printed both notes, and the file's checksum was the same before and after. Reading does not change the file.

A file you formatted by hand would be reformatted on the first change. The notes' content stays the same, and no `tags` key is added until a note is tagged.
